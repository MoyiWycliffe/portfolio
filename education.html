What I Study

More than just code.

Software engineering is a wide field. These are some of the areas that shape how I approach development and problem solving.

Programming

Programming concepts, algorithms, data structures, abstraction, modularity and writing maintainable code.

Software Architecture

Understanding how components interact, how systems are structured and how software can evolve without becoming impossible to maintain.

Databases

Relational databases, SQL, schema design, relationships, indexing, queries and application data modelling.

Cybersecurity

Web security, HTTP, DNS, SSL/TLS, security headers, vulnerabilities, attack surfaces and defensive thinking.

Cloud & Infrastructure

Deployment, hosting, DNS, cloud services, Git workflows, server configuration and understanding production systems.

APIs & Backend Systems

REST APIs, authentication, server-side logic, request handling, integrations and communication between systems.

Version Control

Git, GitHub, branching, merging, conflict resolution, project history and collaborative software workflows.

Web Engineering

Frontend interfaces, responsive layouts, browser behaviour, JavaScript, backend integration and production websites.

Problem Solving

Breaking large problems into smaller systems, debugging, researching, testing assumptions and iterating toward a working solution.

Learning Beyond Class

The real laboratory.

Some of the most valuable lessons come from trying to build something that actually has to work.

Building my own projects means dealing with the things that assignments often simplify: deployment failures, database connections, authentication bugs, CORS, DNS, hosting, security, performance, product decisions and users.

Engineering Philosophy

How I turn knowledge into skill.

Learn

Understand the principles before blindly copying implementations.

Build

Apply the concept to an actual system where requirements and edge cases exist.

Break

Debug failures, question assumptions and understand what actually went wrong.

Iterate

Improve the implementation instead of treating the first working version as the final version.

Still Learning

The degree is the
beginning, not the finish line.

Software changes too quickly for learning to stop at graduation. The goal is to keep building, researching, experimenting and becoming a better engineer long after the classroom ends.
